# Expense review v1
Run scripts/sql/business-expense-candidate.sql in the intended PostgreSQL database before activation. Founder-only UI /fisio/finanzas/gastos-pendientes. Manual candidates and advisory ingestion are separate from ledger transactions.
Sources may submit only through POST /api/integrations/expense-candidates with a distinct GROK_EXPENSE_INGEST_TOKEN (>=32 chars). JSON: source (gmail|stripe|bank|subscription), sourceRef (stable provider id), merchant, description, amountCents, currency EUR, date YYYY-MM-DD, category (software|sueldos|marketing|otros). No secrets or patient data. No connector is activated by this commit. Same source identity cannot overwrite financial facts; duplicate amount and date in the existing ledger requires explicit additional confirmation. Review uses an atomic transaction; no ledger entry from ingestion alone. Approving writes type=expense to the existing ledger; rejecting preserves the candidate and reason. No payout, payment or bank operation is implemented.
Potential cross-source duplicates on different dates or amounts still require human reconciliation. Dates represent actual paid expense date, not merely invoice creation. Avoid double counting fees already reflected in net receipts; inspect accounting convention before adding Stripe connectors.
Tests: npx tsx scripts/test-business-expense-candidates.ts; verify auth, same-reference conflict, concurrent approval, rejection, duplicate warning and ledger update with synthetic records before production.
